# Поиск по нескачанному и чат консультанта — архитектура

Цель: найти любую книгу за секунды, скачать полную и не-спонсорскую запись одной кнопкой (или получить ссылку),
а советоваться — в обычном чате, где каждый совет сразу ставится в очередь или уходит в Telegram.

## Иерархия поиска (от дешёвого к дорогому)

| Уровень | Что | Скорость | Где |
|---|---|---|---|
| L0 | Библиотека: скачанное + каталог манифестов | мгновенно | `items`, `library_match` |
| L1 | **Каталог источников**: локальный индекс открытых источников (каналы Булдакова и «Шарков — Аудіокниги Українською», полный `F-buldakov.json`, кэш knigavuhe/akniga/archive.org) | < 50 мс, FTS5 trigram | `abook_catalog.py`, `src_items` |
| L2 | Живой поиск по площадкам: YouTube (видео и плейлисты), archive.org, knigavuhe/akniga на лету | 5–30 с | `abook_find._run_platforms` |
| L3 | ИИ с WebSearch: Claude (Opus) + Antigravity (Gemini) параллельно, разбор запроса, запросы на ru/uk/en | 30–60 с, ≈ $0.2 | `abook_find.run_claude/run_agy` |

Каждый уровень кормит кэш нижнего: всё, что нашли L2/L3, ложится в L1, поэтому повторный поиск уже мгновенный.

## Проверки перед «Скачать»

- **Доступность**: записи «только для спонсоров» (members-only, `availability=subscriber_only|premium_only|needs_auth`)
  в выдачу не попадают. Пример: «Дверь номер три» из каталога Булдакова — members-only, `abook get` падал.
- **Полнота без скачивания**: длительность против ожидаемой (≥ 55 %, радиоспектакль ≥ 12 %), плейлист — пропуски и
  порядок частей, серии «Часть 1/2/3» склеиваются в одну запись и проверяются на непрерывность номеров.
- **После скачивания**: `abook-check <id> --json` (стыки, обрезка, то ли произведение).
- Кэш проверок yt-dlp — 7 дней по URL.

## Чат консультанта («Что дальше»)

- Обычный чат: разговоры слева, лента с прокруткой, поле ввода последним рядом, Enter — отправить, Shift+Enter —
  перенос. Сообщение появляется в ленте сразу; пока Claude думает — фаза, таймер и «Остановить».
- Каждый совет: «+ в очередь» и «✈ в Telegram» одной кнопкой (`POST /api/find/act {action, item_id|author+title}`):
  - книга на диске → сразу;
  - в каталоге, не скачана → загрузка; «в очередь» ставится сразу, Telegram — после загрузки;
  - вне библиотеки → поиск полной записи с автоскачиванием; действие — после загрузки; несколько равных
    вариантов или ничего → кнопка «выберите запись →» ведёт к этому поиску во «Найти».
  - Отложенные действия — таблица `rec_actions`, фоновый поток доводит их и после перезапуска сервера.
- Контекст ответа: анкета, отзывы с весами, память консультанта, «не интересно», карта связей, 12 последних реплик.

## Память и обучение вкуса

- **Короткая память** — факты консультанта (`consultant_memory`), правятся во «Найти».
- **Векторы признаков** — карта связей (`book_features`): темы, мотивы, тон, приём, герой… с IDF; соседи и «мосты».
- **Своя модель вкуса** (следующий шаг): логистическая регрессия на векторах признаков по оценкам отзывов
  (stdlib, < 1 с на 600 книгах) → балл «понравится» для любой книги с признаками, включая записи L1. Признаки для
  кандидатов L1 считаются лениво той же пачкой Sonnet только для топа выдачи. Модель — переранжирование, не замена
  Claude: Claude объясняет и прыгает «мостами», модель отсеивает то, что точно не зайдёт.
- **Obsidian** (следующий шаг): одностороннее зеркало в `~/abook/vault/` — заметка на книгу (оценка, отзыв, признаки
  как `[[ссылки]]`), заметка на признак, память консультанта, разговоры. Граф Obsidian тогда и есть карта связей.
  Правки идут через приложение, vault пересобирается — без конфликтов двух источников правды.

## Источники

Список каналов — `~/abook/sources.json` (расширяемый). Сайты: knigavuhe.org, akniga.org, archive.org — открываются
отсюда; audioknigi.club, uaudio.com.ua — нет (проверено 01.10.2026). VK и Rutube из этого WSL не открываются.

## Этап 2: «почти весь интернет» без расхода токенов (01.10.2026)

Принцип: **ИИ никогда не ищет и не видит каталог целиком.** Поиск — локальный индекс + векторы, ноль токенов.
ИИ получает только 20–40 уже отобранных кандидатов короткими строками и объясняет/выбирает.

1. **Широкий каталог (метаданные, не аудио).** Полный обход открытых каталогов вежливо (≈ 1 запрос/с, инкрементально):
   knigavuhe (постраничный каталог), akniga (sitemap; только ссылка — плеер зашифрован), archive.org (≈ 34 тыс.
   русских аудио + LibriVox), каналы YouTube из `sources.json`. Самообучение списка каналов: канал, который
   ≥ 3 раз дал хорошую запись в живом поиске, сам добавляется в обход. Ожидаемо 100–200 тыс. записей, ≈ 200 МБ SQLite.
2. **Произведения, а не записи.** Записи склеиваются в «произведение» (нормализованные автор+название, варианты ru/uk/
   оригинал): одна строка выдачи = книга, внутри — все записи с чтецом, длительностью, площадкой, доступностью.
3. **Гибридный поиск.** FTS5 trigram (опечатки, части слов) + семантические векторы (multilingual-e5-small, 384 изм.,
   локально, отдельный venv `~/abook/.venv-vec`, сервер остаётся на stdlib). Векторы float16 в SQLite, поиск полным
   перебором (200 тыс. × 384 — десятки мс). Слияние выдач — RRF. Запрос «мрачное про космос, коротко» работает без ИИ.
4. **Вектор вкуса.** Взвешенное среднее векторов оценённых книг (оценка минус средняя) → «понравится ли» для любой
   записи каталога; поверх — логистическая регрессия по признакам карты связей, когда отзывов станет больше.
5. **Экономия контекста консультанта.** Сейчас в промпт уходит весь §5 CATALOG (≈ 83 тыс. символов, ≈ $0.48 за ответ).
   Вместо него — RAG: гибридный поиск по тексту сообщения + вкус + мосты карты связей → 40 кандидатов строкой
   `id | автор — название | ч | чтец | 3 признака` (≈ 1 тыс. токенов). Ожидаемо в 4–6 раз дешевле и быстрее.

## Память (архитектура, 01.10.2026)

Принцип: **в промпт попадает не память, а выборка из неё под текущее сообщение**, с жёстким бюджетом токенов.
Слои — как у человека: события → выводы → навыки; каждый слой дешевле и короче предыдущего.

| Слой | Что хранит | Как пишется | Как попадает в ответ |
|---|---|---|---|
| 1. События (эпизодическая) | всё сырое: реплики чата, 👍/👎/«читал», отзывы, загрузки, отправки в TG, анкета | append-only таблица `events`, без ИИ | никогда целиком; только через слои 2–4 |
| 2. Факты (семантическая) | короткие утверждения о вкусе и обстоятельствах с типом, уверенностью, источником, датой | «консолидация» — дешёвый вызов (Haiku/Sonnet) раз в N событий: дедуп, разрешение противоречий (свежее и «от вас» побеждает), слияние | векторный поиск: 8–12 фактов, релевантных сообщению, а не все |
| 3. Модель вкуса (численная) | центроиды «+» тегов профиля и любимых книг, анти-центроиды «−», бета-счётчики (лайки/дизлайки) по признакам карты связей, веса реранка | онлайн-обновление на каждую реакцию (Rocchio + Байес), без ИИ | не текстом: ранжирует кандидатов |
| 4. Знания о мире | произведения ↔ записи ↔ авторы ↔ признаки, рейтинги, доступность | краулеры (sitemap/инкремент), склейка сущностей ru/uk/en, кэш проверок | 40 кандидатов строкой ≈ 25 токенов |
| 5. Рабочая память чата | последние 6 реплик дословно + свёрнутое резюме более ранних + ограничения этого разговора («до 5 часов», «без ИИ-голоса») | резюме пересчитывается, когда история выходит за бюджет | целиком (≤ 1,5 тыс. токенов) |

**Бюджет промпта (≈ 7 тыс. токенов вместо 25):** правила 1,2k · профиль-выжимка 1,5k · факты 0,8k · кандидаты 2k ·
разговор 1,5k. Стабильная часть (правила + профиль) идёт первой — её кэширует Claude (prompt caching), платится
только хвост. Инкогнито = только слой 5 и слой 4.

**Забывание:** у факта период полураспада (вкус — год, контекст «сейчас хочу короткое» — неделя), слабые и
опровергнутые выпадают при консолидации, автофактов ≤ 80. Факты, поправленные вами, не стареют.

**Оценка:** leave-one-out по любимым книгам анкеты (hit@10, MRR) и доля 👍 среди советов — каждая правка памяти
и ранжирования проверяется по ним, а не «на глаз».

**Obsidian:** двустороннее зеркало `~/abook/vault/`: заметка на факт, книгу, тег вкуса и разговор, связи — `[[ссылками]]`.
Граф Obsidian = карта вкуса. Правка заметки в Obsidian импортируется как факт «от вас» (по id в frontmatter и mtime).
