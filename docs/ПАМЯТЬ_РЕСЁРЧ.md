# Память для ИИ-приложений — ресёрч и советы

Обзор подходов к долговременной памяти ассистентов (на 10.2026) и выбор для abook. Цель — чтобы в другом проекте
можно было быстро решить, что взять, и не повторить ошибок. Реализация abook — `docs/ИИ_И_ПАМЯТЬ.md` §3 и
`abook_memory.py`.

## 1. Общая схема любой памяти

1. **Запись** — из диалога или событий выделяются факты/сущности (обычно отдельным вызовом модели).
2. **Хранение** — векторная база (поиск по смыслу), граф (кто/что/как связано), обычная БД (структура).
3. **Обновление** — новое сравнивается со старым: добавить / обновить / удалить / слить.
4. **Выборка** — под текущий вопрос достаётся немногое и подкладывается в промпт.

Решения различаются тем, **кто решает, что помнить** (код или сама модель), и **в каком виде** это лежит
(текст, граф, числа).

## 2. Готовые решения

| Решение | Как работает | Сильное | Слабое |
|---|---|---|---|
| **Mem0** | После каждого обмена модель извлекает факты; для каждого ищет похожие в векторной базе, вторая модель решает add / update / delete / noop. Перед ответом — поиск фактов по смыслу; есть вариант с графом. | Готово за час, хорошо для персонального ассистента | 1–2 вызова модели на сообщение; память только текстовая |
| **Letta (MemGPT)** | Модель сама управляет памятью, как ОС оперативкой: «ядро» (короткие блоки в промпте), «архив» (векторное хранилище), история; инструменты «запомнить / найти / переписать блок». | Агент сам решает, что важно; долгие сессии | Сервер; модель тратит токены и шаги на управление памятью; менее предсказуемо |
| **Zep / Graphiti** | Граф знаний во времени: сущности и связи со сроком действия («с … по …»); противоречие закрывает срок старого факта, а не стирает его. Поиск: текст + векторы + обход графа. | Лучшее для «что было верно тогда», многих сущностей и связей | Граф и сервер; извлечение сущностей стоит вызовов модели |
| **LangMem** | Кирпичи: семантическая (факты), эпизодическая (удачные примеры), процедурная (модель правит свой системный промпт по опыту); фоновое «осмысление» после разговора. | Гибкость; процедурная память — редкость | Собирать самому; привязка к экосистеме LangChain |
| **Память провайдеров** (ChatGPT memory, Claude memory / Projects, инструмент памяти Claude API — модель читает и пишет файлы в «папку памяти») | Провайдер хранит заметки и подставляет сам | Ноль работы | У каждого провайдера своя; мало контроля; не переживает смену модели |
| **RAG по истории** | Все сообщения — в векторную базу, перед ответом — похожие куски | Проще всего | Не обобщает, тащит шум, не забывает, не разрешает противоречия |

## 3. Что выбрано в abook и почему

**Своя система поверх SQLite** — гибрид лучших идей:

- **из Mem0** — извлечение фактов с решениями add / update / delete / merge, но пачками раз в 8 событий
  (дешевле: ≈ $0.05 на сводку Haiku), а не на каждое сообщение;
- **из Letta / LangMem** — слои: журнал событий отдельно от фактов; «ядро» самых весомых фактов всегда в промпте;
- **своё** — вкус числами (оценки, реакции, центры вкуса по тегам профиля), а не текстом; забывание по периоду
  полураспада; выборка с разнообразием (MMR); жёсткий бюджет разделов промпта; инкогнито;
- **Obsidian** — зеркало для человека (посмотреть и поправить), не источник правды.

Почему не готовое: данные структурированные (оценки, теги, выбор), пользователь один, всё локально и офлайн,
память должна быть одной для Claude и Gemini и синхронизироваться одним файлом. Серверы и векторные базы
здесь — лишние движущиеся части.

Слабые места (честно):

- **Сводка может переобобщить.** На тесте из одного 👎 вышло «Мартин и его творчество не по вкусу». Лечится
  строгим правилом «одно событие → уверенность ≤ 0.4» и подтверждением повторами.
- **Нет сроков действия фактов** (как в Zep) — противоречия решаются только свежестью.
- **Нет отдельной оценки качества памяти** — меряется только итоговый подбор (leave-one-out).

## 4. Как выбирать в другом проекте

| Ситуация | Что взять |
|---|---|
| Один пользователь, локально, структурированные сигналы (оценки, теги, выбор) | своя система поверх SQLite, как abook |
| Много пользователей, свободные разговоры, нужно быстро | Mem0 |
| Долгоживущий автономный агент, сам ведёт свои заметки | Letta или инструмент памяти Claude API |
| Много сущностей и связей, важно «что было верно когда» (CRM, поддержка, истории) | Zep / Graphiti |
| Агент должен улучшать собственные инструкции по опыту | процедурная память в духе LangMem |
| Короткие сессии, память почти не нужна | история разговора + резюме, без отдельной системы |

## 5. Советы — что работает везде

1. **В промпт — выборка под вопрос с лимитом, а не вся память.** Это главный рычаг экономии токенов
   (в abook 86 → 17 тыс. символов, $0.45 → $0.12).
2. **Сырое отдельно от выводов.** Журнал событий никогда не идёт в промпт; факты — сжатая выжимка из него.
   Тогда выводы можно пересчитать заново, если поменялась логика.
3. **У каждого факта — источник, уверенность, дата.** Без этого невозможно исправить, забыть или объяснить.
4. **Слова человека важнее выводов модели.** Факты «от пользователя» не стареют и не удаляются автоматически.
5. **Забывание обязательно.** Вес = уверенность × 0.5^(возраст / период): вкус — год, «сейчас хочу X» — недели.
   Предел на число автофактов.
6. **Пишите пачками и дешёвой моделью.** Сводка раз в N событий на быстрой модели, а не умной моделью на каждое
   сообщение.
7. **Разнообразие в выборке (MMR)** — иначе в промпт попадут пять почти одинаковых фактов.
8. **Стабильное — первым.** Правила и профиль в начале промпта кэшируются провайдером; изменчивое — в конце.
9. **Длинный разговор — резюме + последние N реплик**, а не вся история.
10. **Режим «без памяти» (инкогнито)** — и для пользователя, и для отладки.
11. **Память не должна зависеть от провайдера модели** — иначе смена Claude ↔ Gemini её обнуляет.
12. **Меряйте.** Набор проверок «спрятать известный факт / любимую книгу — найдёт ли» и доля полезных советов;
    без этого любая правка памяти — на глаз.
13. **Структурированные сигналы — числами, не текстом.** Оценки, реакции, теги лучше работают в ранжировании,
    чем фразы в промпте.

## 6. Что добавить в abook дальше

- сроки действия фактов (`valid_from` / `valid_to`) вместо удаления — противоречие закрывает старый факт;
- правило уверенности для единичных событий и подтверждение повторами;
- небольшой набор проверок качества памяти (извлечение, обновление, выборка) рядом с метрикой подбора.
