# Как работает abook — обзор приложения

Состояние на 01.10.2026. Подробности по каждой части — в документах, на которые ведут ссылки.

## 1. Из чего состоит

```
Аудиотека.exe (Tauri, Windows) ──wsl.exe──> ~/.local/bin/abook-ui ──> abook review (Python, порт 8790)
                                                                    ├─ library.db (SQLite WAL): библиотека, каталог, профили, память
                                                                    ├─ abook_vec (демон векторов, GPU/CPU)
                                                                    ├─ claude / agy (провайдер ИИ, по запросу)
                                                                    └─ фоновые работники: поиск, загрузки, действия, Telegram
```

- **Сервер** — один процесс на стандартной библиотеке Python, без фреймворков. Страницы собираются из строк
  (`abook_*_ui.py`) на дизайн-ките cosmos-kit.
- **База** — один файл `~/abook/library.db`: библиотека и прослушанное, каталог источников (`src_items` → `works`),
  векторы, граф ассоциаций, профили, чаты, память.
- **Десктоп** — Tauri-оболочка показывает сплэш, при необходимости поднимает сервер через `wsl.exe` и закрывает
  его при выходе (`desktop/README.md`). Без десктопа — ярлык `abook-ui-desktop` или `abook-ui` в браузере.

## 2. Запуск с нуля (после перезагрузки)

1. Windows стартует, WSL ещё спит. Запуск `Аудиотека.exe` будит WSL и запускает `abook-ui --no-browser`.
   Оболочка ждёт ответа до 60 с, при неудаче показывает кнопку «Повторить».
2. Сервер открывает базу (WAL), сам создаёт недостающие таблицы (`CREATE TABLE IF NOT EXISTS` в каждом модуле)
   и отвечает через ≈ 2 с.
3. Фоном поднимается демон векторов. Сначала он берёт GPU-окружение `/mnt/d/VideoDownloader/.venv-vec-gpu`,
   иначе CPU-окружение `~/abook/.venv-vec`. Пока демон греется, поиск идёт только по тексту (FTS), без ошибок.
4. Профиль «Основной» пустой; мастер настройки (`/api/setup`) предлагает выбрать провайдера ИИ
   и пройти анкету.

Проверено 01.10.2026 после удаления всех профилей. Сервер запускали в чистом окружении (`env -i`, login shell),
как это делает оболочка. Результат: главная отвечает 200, ошибок JS нет, поиск по каталогу занимает 10 мс,
демон векторов работает на GPU.

Что может помешать: не смонтирован диск D: (тогда недоступно GPU-окружение, а `~/abook/.venv-vec` —
симлинк на него). Поиск при этом работает только по тексту. Вернуть CPU-вариант:
`ln -sfn ~/abook/.venv-vec-cpu ~/abook/.venv-vec`.

## 3. Основные сценарии

| Сценарий | Как идёт | Где код |
|---|---|---|
| Поиск книги | FTS5 trigram по произведениям, при наличии векторов — гибрид через RRF. Слабое совпадение запускает переписывание запроса моделью (вечный кэш `query_alias`). Записи «только для спонсоров» отсеиваются | `abook_catalog.py: search_works`, `abook_find.py: query_variants` |
| Поиск в сети | Работник опрашивает источники параллельно и отдаёт результат, как только найдено `FAST_GOOD=4` хороших записей или прошло `FAST_WAIT=20` с; остальное догружается. Полноту записи проверяет без скачивания (`probe`, `assess`) | `abook_find.py` |
| Действие одной кнопкой | «В очередь», «В Telegram», «Ссылка», «Скачать» пишутся в `rec_actions`, выполняет их фоновый работник | `abook_links.py: rec_action, _act_worker` |
| Скачивание и Telegram | Части сверяются с длительностями на сайте, склеиваются (допуск 1 с + 0,1 с × части), проверяются декодированием. В Telegram уходит один файл с подобранным битрейтом, перед отправкой — `verify_volume`. Оригиналы не режутся | `abook`, `abook-tg`, раздел «Аудио» в `ДЛЯ_АГЕНТОВ.md` |
| Чат-консультант | Промпт собирается так: стабильный префикс (правила, профиль), затем выборка памяти под вопрос (MMR, бюджет), ассоциации из графа, кандидаты из каталога. Ответ потоковый: текст, затем `<<<DATA` и JSON с карточками. Есть «стоп», «другой ответ», правка и инкогнито | `abook_links.py`, `abook_memory.py`, `ИИ_И_ПАМЯТЬ.md` |
| Память | Журнал `mem_events` раз в 8 событий сводится Haiku в факты. У фактов есть уверенность, источник и затухание; слова пользователя не стареют | `abook_memory.py`, `ПАМЯТЬ_РЕСЁРЧ.md` |
| Статистика | Только прослушанное: часы, авторы, жанры, оценки | `abook` (раздел stats) |
| Синхронизация | Личные данные хранятся в приватном git-репозитории данных, плюс зеркало в Obsidian для чтения и правки | `abook_sync.py`, `abook_vault.py` |

## 4. Векторы и граф ассоциаций — что сделано и что дало

**Сделано:**

- **Векторы.** Модель e5-small (384 измерения) посчитала 117 139 векторов, по одному на произведение.
  На RTX 2070 это заняло ≈ 25 мин, на CPU ушло бы несколько часов (`GPU.md`).
- **Граф.** Для каждого произведения взяты 12 ближайших соседей (1,34 млн рёбер). Произведения разбиты на
  360 тем методом k-means, темы подписаны. Найдено 147 тыс. «мостов» — книг на стыке тем. Модуль —
  `abook_assoc.py`, чат получает из графа блок ASSOCIATIONS.

**Что дало на проверочном наборе.** Набор: 6 профилей и 32 книги, которые люди реально слушали, из них 23 есть
в каталоге. Книгу прячут и смотрят, найдёт ли её подбор.

| | hit@10 | hit@40 | MRR |
|---|---|---|---|
| до векторов и графа | 0 из 23 | 0 из 23 | 0,000 |
| после | 2 из 23 | 4 из 23 | 0,065 |

Выводы:

- **Поиск по названию** («убик», «дюна») векторы почти не улучшают: его решают FTS и переписывание запроса.
- **Подбор «что ещё послушать»** вырос с нуля до заметного, но слабого уровня. Основной прирост дал профиль
  с понятным вкусом (MRR 0,26); у остальных близко к нулю.
- **Главное ограничение — мало данных о вкусе:** 1–13 книг на профиль. Индексы готовы и дешёвы в работе
  (вектор запроса считается за 30–50 мс на CPU), их ценность вырастет вместе с числом оценок.

**Отложено:** дообучение адаптера и реранкера на разметке (3 125 книг размечены). Ранние метрики показали
небольшой рост по соседям и мостам и падение MRR, поэтому работа отложена до появления большего числа оценок.

  `~/abook/library.db` и в приватном репозитории синхронизации.
- 01.10.2026 все профили и личные данные удалены. Перед удалением сделана копия:
  `~/abook/db-backups/library-before-profile-wipe-*.db`. Каталог, векторы, граф и аудио сохранены.
