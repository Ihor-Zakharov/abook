# Для агентов: что используется и какие были грабли

Самое ценное из разработки abook (09–10.2026) в одном месте — чтобы агент в другом проекте взял работающее и не
наступил на те же грабли. Подробности — `docs/NOTES.md`, архитектура — `docs/ПОИСК_И_ЧАТ.md`, память —
`docs/ИИ_И_ПАМЯТЬ.md` и `docs/ПАМЯТЬ_РЕСЁРЧ.md`.

## 1. Стек — что используется и почему

| Слой | Что | Почему так |
|---|---|---|
| Сервер | Python 3 stdlib (`http.server`), один файл `abook` + модули `abook_*.py` | ноль зависимостей, запускается где угодно; тяжёлое — в отдельных venv |
| База | SQLite (WAL), FTS5 `tokenize='trigram'` | 180 тыс. записей ищутся за 5–40 мс; один файл — легко копировать и синхронизировать |
| Векторы | multilingual-e5-small (384), fastembed/ONNX в `~/abook/.venv-vec`, демон по stdin/stdout | без torch и GPU, ≈ 650 МБ; полный перебор в numpy ≈ 22 мс на 200 тыс. |
| ИИ | `claude -p` (Claude Code) или `agy` (Antigravity) — консольные программы, а не API-ключи | подписка вместо оплаты токенов; один контракт в `abook_llm.py` |
| Скачивание | yt-dlp + ffmpeg/ffprobe | yt-dlp берёт YouTube, archive.org, прямые mp3; ffmpeg — склейка, декод-проверка |
| Проверка смысла | faster-whisper (отдельный venv) + Claude: фрагменты начала, конца и стыков | ловит обрезки, неправильный порядок частей, «не та книга» |
| Интерфейс | одна HTML-строка в Python + дизайн-кит cosmos-kit (тёмная сцена WebGL) | без сборщиков; кит держит правила линтером |
| Десктоп | Tauri 2 + WebView2, кросс-сборка из WSL через cargo-xwin | exe ≈ 3–10 МБ, ядро Chromium из Edge |
| Синхронизация | приватный git-репозиторий с одним JSON | без сервера; слияние «свежее побеждает» |

## 2. Приёмы, которые стоит переносить

1. **ИИ не ищет и не видит базу целиком.** Локальный поиск отбирает 40 кандидатов, модель выбирает и объясняет.
   Промпт 86 → 17 тыс. символов, цена ответа $0.45 → $0.12.
2. **Потоковый ответ с разделителем:** модель пишет текст, затем строку `<<<DATA` и JSON. Текст идёт в интерфейс
   по мере генерации, JSON разбирается и проверяется в конце. Без `--json-schema`, которое ломает поток.
3. **Действие одной кнопкой с отложенным выполнением** (`rec_actions` + фоновый поток): «в Telegram» у
   нескачанной книги = найти → скачать → проверить → отправить; переживает перезапуск.
4. **Ступени поиска от дешёвого к дорогому:** библиотека → FTS по каталогу → векторы → переписывание запроса
   быстрой моделью (кэш навсегда) → сеть + ИИ. Дорогая ступень — только если дешёвые не дали сильного ответа.
5. **«Быстрый путь» в поиске по сети:** если площадки уже дали ≥ 4 записей с точным названием, ИИ ждать ≤ 20 с;
   ожидаемую длину книги взять из 3-й четверти длительностей найденных записей. 142 с → 38 с, без затрат ИИ.
6. **Память слоями** (журнал → факты → выборка MMR → бюджет), забывание по полураспаду, слова человека не стареют.
7. **Проверка без скачивания:** `yt-dlp -J` (плейлист — `--flat-playlist`) даёт доступность, длительность, части;
   «только для спонсоров» видно по `availability`.
8. **Жалоба на источник действует сразу** (помечает запись в каталоге, убирает из выдачи), а не «в отчёт».
9. **Кэш на всё дорогое:** проверки yt-dlp — 7 дней, переписанные запросы — навсегда, «Для вас» — 30 минут
   на профиль со сбросом по реакции.
10. **Офлайн-оценка качества** (leave-one-out по любимым книгам: hit@10, MRR) — каждая правка ранжирования
    проверяется цифрой.

## 3. Грабли — и как их обойти

### Окружение (WSL2 на Windows)

- **`pkill -f <шаблон>` убивает собственную оболочку**: шаблон совпадает с командной строкой самой команды.
  Останавливать по PID из `ss -ltnp` или `pgrep` с шаблоном в квадратных скобках: `pgrep -f "[a]book_vec"`.
- **То же в ожидании:** `until ! pgrep -f "abook_catalog.py crawl"` никогда не выйдет — находит сам себя.
- **Свободное место в WSL обманчиво:** `df` показывает сотни ГБ, а ext4.vhdx лежит на C:, растёт и сам не
  сжимается. Тяжёлое (временные файлы склейки, кэши сборки, модели > 1 ГБ) — на D: (`/mnt/d`).
- **`/mnt/c`, `/mnt/d` медленные** (drvfs): база и код — в ext4 WSL, на Windows-диске — только результат.
- **Холодный старт WSL после включения ПК — 10–30 с:** оболочка должна ждать сервер до минуты со сплэшем.
- **Никогда не `wsl --shutdown` для проверок** — убивает всё, что работает в WSL, включая агентов.

### Git

- **В git worktree `.git` — это файл-ссылка.** Скопировали дерево вместе с ним и сделали `git init` — получили
  коммит в чужой репозиторий. При экспорте исключать `.git`.
- **Перед пушем проверять ВЕСЬ диапазон**, а не свои коммиты: `git log origin/main..main --format=%B | grep -i co-authored`.
  Старый непушенный коммит другой сессии уходит вместе с вашими.
- **Переписывать уже запушенную историю нельзя без явного согласия** — force-push блокируется политикой.
  Для публикации «с чистого листа» — новый репозиторий с одним коммитом текущего состояния.

### Интерфейс

- **Замена текста в JS-строке обрезала конец выражения** → `SyntaxError` → мёртвые кнопки и пустая сцена при
  живом сервере. После любой правки фронта — проверка консоли headless-браузером (CDP `Runtime.exceptionThrown`),
  а не только снимок.
- **Классы кита заняты:** `.empty` — компонент кита (свой стиль пустого состояния сломал раскладку чата);
  `.in{width:100%}` растягивает селекты столбиком — `.in.auto`. Перед своим классом — `check.py --classes`.
- **Белая цифра на белом кружке:** правило «активный» перекрасило цифру у шага «сделан + активный». Проверять
  все комбинации состояний.
- **Плавная прокрутка (`scroll-behavior:smooth`) у ленты чата** анимирует каждое открытие. Ставить положение
  сразу, плавно — только по кнопке.
- **Пустой блок с отступом + нижний запас области** дали прокрутку на главной. Мерить `scrollHeight` против
  `innerHeight` на реальных размерах окна (у пользователя 2560×945 и 2000×860), а не «на глаз».
- **Эмодзи и хэштеги в названиях с YouTube** сдвигают строки и выглядят мусором — чистить при показе.

### Поиск и данные

- **bm25 штрафует длинные записи:** у «Мартина Идена» длинный список чтецов — он проигрывал «Мартынову».
  Брать широкий пул кандидатов (≥ 400), потом пересчитывать своей формулой.
- **Проверка «сильного совпадения» по основам слов ложно срабатывает** («Хоббит» ≈ «Хобби»). Сравнивать целые слова.
- **Векторы для каждой записи — двойная работа:** записи одной книги почти одинаковы. Считать по произведениям.
- **Каталоги YouTube отдают названия автопереводом на английский** — просить заголовки на языке канала.
- **Спонсорские записи выглядят как обычные** в выдаче поиска; отсеивать по `availability` и проверке `-J`.
- **Снимок каталога приносит отметку «индекс построен»** — после импорта индекс надо пересобрать принудительно.
- **Копия живой базы во время записи может оказаться битой** — копировать через `sqlite3 db ".backup путь"`.

### ИИ

- **`--json-schema` с `{"type":"object"}` без полей** — модель возвращает пустой объект. Либо полная схема,
  либо ответ без схемы и разбор JSON из текста.
- **Длинный промпт аргументом командной строки** упирается в лимит Linux ≈ 128 КБ — передавать файлом.
- **Сводка памяти моделью переобобщает** (из одного 👎 — «не любит автора целиком»): правило уверенности для
  единичных событий.
- **Метка фазы «Claude думает» на Gemini** — подписи процесса должны быть нейтральными к провайдеру.

### Процесс с агентами

- **Два агента в одном файле** — только точечные правки (`Edit`), не перезапись файла целиком; заранее делить
  зоны («ты — сборка промпта, я — обработчик чата»).
- **Агенты-тестировщики оставляют headless-браузеры**, которые едят 400 % CPU, — после прогонов проверять процессы.
- **Отчёт «готово» от фонового ожидания проверять:** в момент перезапуска сервера индекс на секунду показал
  «осталось 0». Условие «готово» — два замера подряд.

## 4. Когда это уместно, а когда нет

| Приём | Брать, если | Не брать, если |
|---|---|---|
| Python stdlib-сервер + HTML в строке | личный инструмент, один пользователь, локально; важно «запустится где угодно» | команда фронтенд-разработчиков, сотни экранов, нужен типизированный фронт и сборка |
| SQLite + FTS5 trigram | до миллионов записей на одной машине, поиск по названиям с опечатками и рус/укр написаниями | много одновременных писателей, распределённая система — тогда Postgres (pg_trgm) или поисковый движок |
| Локальные векторы (e5-small, полный перебор) | до ~1 млн записей, смысловой поиск офлайн, без платы за эмбеддинги | десятки миллионов записей — нужен ANN-индекс (HNSW: sqlite-vec, Qdrant); или хватает обычного полнотекстового поиска |
| ИИ через консольные программы (`claude -p`, `agy`) | личный проект на подписке, вызовов — единицы в минуту | продакшн для многих пользователей — API с ключом, очередями, лимитами и наблюдаемостью |
| «ИИ не видит базу, только кандидатов» | база больше контекста или дорого её слать каждый раз | данных мало (влезают в 5–10 тыс. токенов) — проще отдать целиком |
| Потоковый ответ с разделителем `<<<DATA` | нужен и живой текст, и структурированный результат одним вызовом | только структура (без текста для человека) — JSON-схема без потока |
| Действие одной кнопкой с отложенным выполнением | действие состоит из долгих шагов (найти → скачать → проверить → отправить) | действие мгновенное — обычный запрос |
| Ступени поиска от дешёвого к дорогому | у дорогих шагов есть цена или задержка (ИИ, сеть) | все шаги дешёвые и быстрые |
| Переписывание запроса быстрой моделью с вечным кэшем | названия, синонимы, переводы, которые словарём не покрыть; запросы повторяются | запросы уникальные каждый раз (кэш бесполезен) и важна мгновенность |
| Память слоями (журнал → факты → выборка) | ассистент живёт долго и должен помнить вкус/контекст | короткие независимые сессии — хватит истории разговора |
| Синхронизация через приватный git-репозиторий | один-два пользователя, несколько своих устройств, данных мало | совместная работа многих людей, частые одновременные правки — нужен сервер |
| Зеркало в Obsidian | человеку важно видеть и править память своими глазами | память только для машины |
| Tauri вместо браузера | веб-интерфейс уже есть, нужно «настоящее» окно, лёгкий установщик | нужен одинаковый вид на всех ОС до пикселя и встроенный Chromium — Electron; нужна нативность — WinUI/SwiftUI |
| Офлайн-оценка (leave-one-out, hit@k) | есть ранжирование или подбор, который правят итерациями | нет «правильных ответов» даже приблизительно |
| Дизайн-кит с линтером правил | несколько проектов в одном стиле, правки делают разные агенты | один разовый экран |
