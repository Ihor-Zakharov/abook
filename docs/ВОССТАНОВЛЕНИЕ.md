## Команды
```bash
# 1. Продолжить скачивание (безопасно повторять; незаконченные книги начнутся заново)
cd ~/abook && rm -rf staging/*/ && abook get manifests/D-discoveries.json manifests/E-works.json \
  manifests/A-prose.json manifests/B-scifi.json manifests/C-classics.json \
  manifests/G2-russian-classics.json manifests/G1-western-classics.json manifests/H-radioplays.json manifests/I-games.json manifests/J-extra.json F-buldakov-top.json \
  --jobs 12 --engine direct --bitrate 128 --retry-failed > ~/abook/run.out 2>&1 &
# (или просто: bash ~/abook/turbo.sh — то же самое + запрет сна Windows; движок direct, 12 потоков)

abook status | tail -1          # прогресс: done/failed/pending, часы, ГБ
tail -f ~/abook/abook.log       # живой лог
abook sync                      # манифесты+state → база, пересборка файла для ИИ
abook review                    # приложение отзывов http://localhost:8790 (или D:\…\Отзывы.bat)
abook aidoc [--lite]            # пересобрать файл для ИИ

# Проверка библиотеки (безопасно при идущем abook get: in_progress пропускает, пишет state только под блокировкой)
abook verify                    # быстро: файлы на месте, размер совпадает
abook verify --full             # SHA-256, полное декодирование, главы, тишина, сверка длительности с источником
abook verify --full --fix       # сломанное → в .quarantine/ и в failed (ничего не удаляет); затем:
abook get <манифесты> --retry-failed   # перекачает то, что --fix пометил
cd /mnt/d/VideoDownloader/Аудиокниги && sha256sum -c CHECKSUMS.sha256   # независимая сверка без abook
```
То же в приложении: вкладка «Проверка» (кнопки «Быстрая» / «Полная (SHA-256)», только чтение, без --fix).
Проверка, что скачивание идёт: `pgrep -fc 'vydra/bin/yt-dlp'` (direct; ≈ число потоков) или для старого движка
`ps -eo args | grep -c '^/home/ihor/.local/share/uv/tools/vydra/bin/python /home/ihor/.local/bin/vydra d'`.
Остановить: найти PID `pgrep -f '^python3 /home/ihor/.local/bin/abook get'`, убить его и дочерние (не `pkill -f` с шаблоном, совпадающим с командой своего шелла).

## Как `abook get` проверяет каждую книгу (с 26.09)
Книга принимается, только если прошло всё; иначе `failed` с причиной (видна в `abook status` и во вкладке «Проверка»):
- порядок частей явный: (номер ссылки в манифесте, номер в плейлисте); нельзя дубликатов (один источник дважды), пропусков
  в плейлисте (удалённые/скрытые ролики) и нумерованных названий, идущих назад («часть 3» после «части 5») →
  «порядок частей под сомнением: …». Если порядок на самом деле верный — `"order_ok": true` у книги в манифесте
  (для плейлиста с заведомо удалёнными роликами — `"gaps_ok": true`);
- каждая часть по длительности равна тому, что сообщает площадка (±max(2 с, 0,5%)) — ловит оборванные загрузки;
- склейка: длительность = сумма частей, глав столько же, сколько частей, и они начинаются на стыках (±1 с), файл
  полностью декодируется без ошибок и декодированная длина = заявленной (±1 с), нет тишины >10 мин подряд или >20 мин
  всего (>3 мин — предупреждение), объём аудиоданных = сумме частей ±2%;
- SHA-256 считается в staging, файл копируется на D: через `.part` + fsync, перечитывается с D: и сверяется
  (не совпало — копия удаляется, одна повторная попытка); итог пишется в `state.json` и `CHECKSUMS.sha256`.
  Итоговое имя появляется на D: только после всех проверок; брошенные `*.part` чистятся при старте `get`.
- предупреждения (не ошибка): часть <20% медианы, длительность ±5% от оценки манифеста.

`abook verify --full` дополнительно для каждой скачанной книги: SHA-256 (у книг, сделанных старым кодом, он
вычисляется и записывается), главы, декодирование, тишина, и полнота: сверка с длительностью у источника
(для старых mp3 запрашивается один раз через yt-dlp, раз в ~3 с, и кэшируется в state), оценка манифеста ±5%,
`~/abook/text-estimates.json` (объём текста), фразы «сокращ…», «избранные», «главы 1–9» в манифестах →
список «Требуют ручной проверки полноты». Итог: OK / неполный / подозрительно / требует ручной проверки,
и «гарантированно проверено: N из M» — только книги, прошедшие всё.

**Важно:** `abook get`, запущенный до 26.09 ~10:45, работает на СТАРОМ коде (он загружен в память) и новых проверок
не делает; они включатся после его перезапуска (`bash ~/abook/turbo.sh`). Файлы, сделанные старым кодом,
покрывает `abook verify --full`.

## ИИ-проверка полноты книги: `abook-check` (добавлено 2026-09-26)
`abook-check <id | автор/название>` — нарезает из готового файла фрагменты (начало 90 с, конец 120 с, каждый стык
частей 45+45 с по главам файла, 3×60 с из середины), распознаёт их faster-whisper (small, CPU int8; venv
`~/abook/.venv-check`, кэш `~/abook/check-cache/<id>/`), спрашивает Claude через `claude -p` без инструментов и
печатает вердикт: полная / вероятно полная / неполная / неверный порядок / не то произведение / нельзя определить,
с уверенностью, таблицей стыков, цитатами и моментами «что послушать». Отчёт — `~/abook/check-reports/<id>.json`.
```bash
abook-check --list-risky              # что проверять первым (short/long по объёму текста, предупреждения, заметки)
abook-check <id> [--model opus] [--clips 6] [--json]
abook-check <id> --show               # сохранённый отчёт;  --prompt-only — промпт для ручной вставки в любой чат
```

Время при идущей загрузке: 1–2 с распознавания на секунду фрагмента (книга без частей ≈ 8 мин, 2 части ≈ 10 мин,
+1,5–3 мин на стык), Claude sonnet ≈ 20 с и ≈ $0.03; повтор из кэша ≈ 20 с. state.json/манифесты только читает.
Навык Claude Code: `~/.claude/skills/abook-spotcheck/` (срабатывает на «проверь книгу», «выборочная проверка»,
«вся ли книга») — как выбрать книгу, читать отчёт, что слушать ушами, как отправить на перекачку
(`abook verify --full --fix` → `abook get … --only <id> --retry-failed`) и где записать результат.
Промпт для любого чата: `~/abook/ПРОМПТ_ПРОВЕРКИ_КНИГИ.md`.

Страница прогресса (`abook-progress`, :8791) обновлена: понимает .m4a и строки лога движка direct (скачивание части

## Telegram (добавлено 26.09): отправка книг в свой канал/группу

CLI `abook-tg` шлёт аудиокниги из библиотеки в собственный Telegram-канал/группу от вашего аккаунта (MTProto,
Telethon — лимит файла 2 ГБ; Bot API с его 50 МБ не подошёл бы). Venv `~/abook/.venv-tg` (там `telethon`+`cryptg`,
системный python их не видит, поэтому у `abook-tg` свой шебанг на venv).

**Секреты (никому не показывать, не коммитить):** `~/abook/telegram.json` (api_id, api_hash, выбранная цель;
chmod 600), сессия `~/abook/tg.session` (chmod 600). Журнал отправленного — `~/abook/tg-sent.json` (том → id
сообщения в Telegram, для докачки после сбоя). Временные тома нарезки большой книги — `/mnt/d/VideoDownloader/
Аудиокниги/.tg-tmp` (не в WSL, чтобы не растить vhdx), удаляются сразу после отправки тома.

```bash
abook-tg setup                          # один раз: api_id/api_hash (my.telegram.org), телефон, код, 2ФА,
                                         # затем список ваших каналов/групп — выбрать номером
abook-tg setup --target                 # сменить только цель (канал/группу), без повторного логина
abook-tg send <id|автор/название> [--dry-run] [--force [--delete-old]] [--quality high|speech|small|original]
abook-tg queue [N] [--profile ИМЯ] [--force] [--quality ...]   # следующие N (по умолч. 3) из очереди приложения
abook-tg status                         # цель, сколько книг/томов/ГБ отправлено
```

**Сжатие (по умолчанию включено — Telegram сам звук не сжимает).** Профили: `high` (высокое, по умолчанию) —
AAC 80 кбит/с моно 44.1 кГц, почти без потерь на слух для речи из обычных ~128 кбит/с стерео источников
(≈36 МБ/ч); `speech` (речь) — 64 кбит/с моно (≈28.8 МБ/ч); `small` (маленький) — 48 кбит/с моно; `original`
(оригинал) — без перекодирования, как раньше. Если исходник и так не хуже цели (битрейт ниже, уже моно) —
перекодирование пропускается само. Кодек — `libfdk_aac`, если собран в вашем ffmpeg, иначе нативный `aac`
(двухпроходный поиск); кодирование — `nice 10`, чтобы не мешать остальной работе. Профиль по умолчанию хранится
в `~/abook/telegram.json` (несекретный ключ `quality`) — меняется флагом `--quality` разово или селектором
«Качество сжатия по умолчанию» во вкладке «Экспорт» приложения отзывов.

Книги длиннее 8 ч (или такие, что том не влез бы в 1,9 ГБ) режутся на тома по 4–6 ч, срез — по границам глав
файла, если они есть рядом с целевой точкой, иначе по времени. С любым профилем сжатия по размеру дробить
почти никогда не приходится раньше правила «>8 ч» (65+ ч ушло бы в 1,9 ГБ даже на 64 кбит/с). Загружается
с прогрессом (сначала «сжатие k/n %», потом «отправка k/n %, МБ/с»), при `FloodWait` от Telegram — пауза и
продолжение. Повторный запуск пропускает уже отправленные тома (докачка после обрыва); `--force` — переслать
заново. Подпись (≤1024 симв.): автор — название, чтец, длительность (всей книги и тома), раздел, «о чём» одной
строкой, хэштеги из раздела/автора + #Короткое/#Длинное.

**В приложении отзывов (`abook review`, вкладка любая, где видна книга)** — кнопка «В Telegram»/«✓ в Telegram»:
карточка, поиск, «Мои отзывы», «Очередь», «Что дальше» (детерминированный список и «Рекомендации ИИ»),
«Библиотека», топ-5 анкеты. Реальная отправка всегда идёт venv-подпроцессом `abook-tg … --json-progress`
(сервер `abook review` — на системном python, там telethon нет); одна отправка за раз, остальные — в очередь.
Вкладка «Экспорт» показывает канал и сколько отправлено. Код: `~/.local/bin/abook_tg.py` (мост, читает
`telegram.json`/`tg-sent.json`, управляет фоновой задачей) + правки в `~/.local/bin/abook`
(`import abook_tg as TG`, `/api/tg/status|send|queue|cancel`, кнопка `tgBtn()` в JS). Подробности и API для
дальнейших правок — `~/abook/NOTES.md`.

Если `abook-tg setup` не запускали — кнопки показывают «не настроено» и не мешают остальной работе.

**С 30.09: TG-очередь и проверка перед отправкой.** Клик «✈ в Telegram» ставит книгу в TG-очередь
(`~/abook/tg-queue.json`, переживает перезапуск `abook-ui`: недоотправленное продолжится само, уже отправленное
повторно не уйдёт). Пометка на книге: «✈ TG-очередь · №k» → «✈ проверка…» → «✈ сжатие k/n %» → «✈ отправка k/n %»
→ «✓ в Telegram». Перед отправкой каждой книги — `abook-check` (или его свежий отчёт, если файл не менялся):
нашёл проблему (неполная / не тот порядок / не то произведение) — книга не уходит, пометка «⚠ проверка: проблема»,
кнопка «всё равно отправить»; проверка недоступна (нет `claude`, лимит, таймаут 15 мин, сбой whisper) —
предупреждение и отправка без неё. Список очереди, отмена, «убрать», «остановить всё» — «Экспорт» → Telegram.
Книги, ушедшие томами по старым правилам, помечены «✓ в Telegram · 3 тома»: клик → подтверждение → переотправка
одним файлом (`--force`). Старые сообщения остаются в канале — удалите вручную (их id — в `tg-sent.json` →
`superseded`) или `abook-tg send <id> --force --delete-old` из терминала.

## Вкладка «Найти» (добавлено 30.09): новая книга по названию, консультант, карта связей

Запуск как обычно: перезапустить `abook-ui` (при первом старте в базу добавятся таблицы; перед этим копия
`~/abook/db-backups/library-pre-find-*.db`). Вкладка «Найти» в рельсе:

- **Поле «Найти»**: название («Пикник на обочине», «Стругацкие Пикник, чтец Кузнецов») — ищет площадки напрямую,
  Claude и Antigravity параллельно, каждую запись проверяет yt-dlp без скачивания, показывает площадку, чтеца,
  длительность, части, «проверено: скачивается», кто нашёл. Однозначно — одна кнопка «Скачать»; иначе карточки.
  Пожелание («что-нибудь как Солярис, но короче») уходит консультанту.
- **Загрузки**: через обычный `abook get` (манифест `~/abook/manifests/ui-requests.json`, 128 кбит/с), по одной
  книге, очередь `~/abook/find-queue.json` переживает перезапуск; логи — `~/abook/find-logs/<id>.log`. После
  скачивания — `abook-check`, книга появляется в библиотеке.
- **Консультант** помнит вкус («Память консультанта» — факты можно править и удалять), советует «мосты» в другие
  жанры с цепочкой «любимая книга → признак → эта книга»; регулятор «ближе ↔ дальше», «удиви меня».
- **Карта связей**: один раз кнопка «Построить карту связей» — ≈ 24 вызова Claude Sonnet (≈ 15 мин в фоне), потом
  только «Досчитать» новые книги. В карточке книги появляется блок «Связи».

Если вкладка ведёт себя странно — остановить загрузку «Отменить» (или `kill` pid из `find-queue.json`), лог книги
смотреть в `find-logs/`. Код и подробности — `NOTES.md`, раздел «Вкладка «Найти»».
